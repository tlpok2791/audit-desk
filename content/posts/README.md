# 네이버 블로그 발행 파이프라인

자동 발행은 하지 않는다. **붙여넣기 직전까지만** 자동화한다.
스마트에디터 창에 사람이 직접 붙여넣고 발행 버튼을 누른다.

## 흐름

```
서류  →  /from-docs  →  drafts/  →  /naver-ready  →  ready/  →  복사·발행  →  /naver-done
                                                                              → published/

주제만 있을 때는 /from-docs 를 건너뛰고 drafts/ 에 손으로 초안을 넣는다.
```

| 폴더 | 무엇이 들어가나 | 누가 넣나 |
|---|---|---|
| `drafts/` | 초안 | `/from-docs` 또는 사람이 직접 |
| `ready/` | 네이버 발행용 원고 | `/naver-ready` |
| `published/` | 발행 후 URL까지 기록된 글 | `/naver-done` |

`/from-docs` 가 서류를 판독해 초안을 만들고, `/naver-ready` 가 네이버 규격으로
변환해 `ready/` 에 넣는다. 전부 Claude 에이전트가 한다 — 별도 API 키가 없다.

## 프론트매터

모든 파일 맨 위에 온다.

```yaml
---
title: 1세대 1주택 비과세, 놓치기 쉬운 요건
category: transfer         # content/categories.json 의 items[].id
keywords: [1세대 1주택, 양도소득세 비과세, 보유기간]   # 핵심 검색어 3~5개
tags: [양도소득세, 1세대1주택, 비과세요건]        # 네이버 태그 10개
kb_refs: []                # 참고할 KB 파일 경로 (없으면 빈 배열)
status: draft              # draft | ready | published
published_url: ""
published_at: ""
---
```

- `category` — `content/categories.json` 의 `items[].id` 중 하나. 네이버 블로그
  카테고리와 1:1로 맞춰 둔 값이다. 홈페이지 블로그 탭이 이 값으로 묶는다.
  모르는 값을 쓰면 `build_posts.py` 가 경고를 찍는다 (죽지는 않는다).
- `keywords` — **핵심 검색어.** 본문에서 몇 번 나오는지 코드가 센다. 태그와 다르다.
- `tags` — 네이버에 붙일 태그 전체. 없으면 `=== 태그 ===` 구획에서 읽는다.
- `kb_refs` — 사실관계 보강에 쓸 KB 파일 경로. `/naver-ready`는 **여기 적힌 파일만** 읽는다.
- `published_url` / `published_at` — `/naver-done`이 채운다.

## ready/ 파일 형식

아래 섹션 구분자를 그대로 쓴다.
홈페이지의 복사 버튼과 `build_posts.py`가 이 구분자를 기준으로 잘라 읽으므로 **이름을 바꾸지 않는다**.

```
---
(프론트매터)
---

=== 제목 후보 ===
1. 첫 번째 제목 (질문형)
2. 두 번째 제목 (정보형)
3. 세 번째 제목 (대상 특화형)

=== 본문 ===
(마크다운 없는 평문. 소제목은 그냥 한 줄.)

[이미지 1 삽입 위치]

(다음 정보 단위)

[이미지 2 삽입 위치]

...

(마무리 · 안내 문구 · 상담 유도)
(상담 유도 문구 — 담백하게 한두 문장)

=== 이미지 제작 목록 ===
이미지 1
- 위치: 도입부 다음
- 목적: 이 글에서 다룰 세 가지 확인 지점을 먼저 보여준다
- 유형: 체크리스트형
- 구성: 집 모양 아이콘 아래 확인 항목 세 줄을 체크박스로 나열
- 화면 문구: 세대 판정 시점 / 보유기간 기산일 / 처분기한
- 스타일: 한국어 중심, 군더더기 없는 세무 인포그래픽
- 비율: 네이버 블로그 가로형

이미지 2
- ...

=== 태그 ===
태그1, 태그2, ... (10개)

=== 리포트 ===
총 글자수: 1,234자 (이미지 자리 제외)
핵심 키워드: 1세대 1주택, 양도소득세 비과세
키워드별 실제 등장 횟수:
- 1세대 1주택: 3회
- 양도소득세 비과세: 4회
이미지 개수: 4개

=== 검토 필요 ===
- [준법] ...
- [근거] ...
- [수치] ...
- [최신성] ...
- [키워드] ...
- [중복] ...
```

### 규칙

- **본문 900~1,500자**를 기본 범위로 한다. 주제가 복잡할 때만 늘린다.
- **이미지 자리는 정보 전달 단위 끝에** 놓는다. 몇 줄마다 기계적으로 넣지 않는다.
  기본 3~5개, 글에 따라 2~6개.
- 이미지 자리표시자는 `[이미지 1 삽입 위치]` 형태다.
  예전 `[이미지: 설명]` 형태도 계속 읽히므로 기존 글을 고칠 필요는 없다.
- `=== 이미지 제작 목록 ===` 의 항목 수는 본문의 삽입 위치 수와 같아야 한다.
  어긋나면 `검토 필요`에 자동으로 표시된다.
- `=== 리포트 ===` 의 숫자는 **모델이 세지 않는다.** `blog_out.py` 가 본문을 직접 세서 채운다.
- `=== 검토 필요 ===`는 지적할 것이 없으면 통째로 빠질 수 있다.
  `[키워드]` `[중복]` `[분량]` `[이미지]` 항목은 코드가 계산해 붙인다.
- `[준법]`은 `/naver-ready`가 `ad-agent`를 **`blog-agent`와 동시에** 돌려 받은 결과를
  합쳐 넣는다. 전문직 광고 규정(공인회계사법 제15조의2 등)에 걸리는 표현이 대상이다.
- `=== 이미지 제작 목록 ===` 이 없는 예전 글도 그대로 읽힌다(형식 위반으로 보지 않는다).

## 홈페이지에 반영하기

`ready/`·`drafts/`는 정적 호스팅에서 직접 읽을 수 없으므로, 목록을 JS 파일로 굽는다.

```bash
python3 build_posts.py      # → src/data/posts.js 재생성
```

글을 추가·변환·발행한 뒤 이 명령을 돌려야 홈페이지 블로그 탭에 반영된다.

## 명령

| 명령 | 하는 일 |
|---|---|
| `/naver-ready <초안경로>` | 초안 하나를 네이버용으로 변환해 `ready/`에 저장 |
| `/naver-done <ready경로> <발행URL>` | `published/`로 옮기고 URL·발행일시 기록 |
