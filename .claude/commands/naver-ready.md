초안 파일 하나를 네이버 발행용으로 변환한다. 자동 발행은 하지 않는다.

## 대상

`$ARGUMENTS`

인자가 비어 있으면 **폴더를 스캔하지 말고** 그대로 멈춘다.
"변환할 초안 경로를 지정해 주세요. 예: `/naver-ready content/posts/drafts/가족인건비.md`" 라고만 답한다.

## 순서

**1. 초안 읽기 — 지정된 파일 하나만**

`$ARGUMENTS` 경로의 파일만 Read한다.
`content/posts/drafts/` 전체를 훑거나 Glob으로 다른 초안을 찾지 않는다. 지정된 하나만 처리한다.

파일이 없으면 경로를 그대로 알려주고 멈춘다.

**2. 프론트매터 확인**

`title`, `category`, `keywords`, `kb_refs`가 있는지 본다. (`tags`는 없으면 변환하며 채운다.)
`category`는 `medical` 또는 `transfer`여야 한다.
필수 항목이 비어 있으면 무엇이 없는지 알려주고 멈춘다. 임의로 채우지 않는다.

**3. KB 사실관계 보강 — kb_refs에 적힌 파일만**

프론트매터 `kb_refs`에 나열된 경로만 Read한다.
`kb_refs`가 비어 있으면 이 단계를 건너뛴다. **KB 폴더를 검색하지 않는다.**
읽은 내용은 초안의 사실관계(요건, 금액 기준, 근거 조문)를 확인·보강하는 데만 쓴다.

KB와 초안이 어긋나면 KB를 신뢰하되, 어긋난 지점을 기록해 두었다가 마지막 보고에 포함한다.

**4. blog-agent 에이전트에 위임**

Agent 도구로 `blog-agent` 서브에이전트를 호출한다. 변환은 직접 하지 않는다.
변환 작업임이 분명하도록 초안 전문과 저장 경로를 함께 넘긴다.

전달할 것:
- 초안 전문 (프론트매터 포함)
- 3단계에서 읽은 KB 내용 중 **관련 대목만** 발췌 (전문을 통째로 넘기지 않는다)
- 저장 경로: `content/posts/ready/<초안과 같은 파일명>`
- 프론트매터의 `status`는 `ready`로 바꾸고, `published_url`·`published_at`은 빈 문자열로 둘 것
- `content/posts/README.md`의 "ready/ 파일 형식" 구분자를 그대로 지킬 것

**5. 결과 확인**

에이전트가 저장한 파일을 Read해서 아래를 확인한다:

- `=== 제목 후보 ===`, `=== 본문 ===`, `=== 이미지 제작 목록 ===`, `=== 태그 ===`,
  `=== 리포트 ===` 다섯 섹션이 다 있는가
- 본문의 `[이미지 n 삽입 위치]` 개수와 이미지 제작 목록의 항목 수가 같은가
- 본문에 마크다운 잔재(`#`, `**`, 줄 앞 `- `)가 남아 있지 않은가
- 말미 안내 문구가 있는가

어긋나면 에이전트에게 고치게 하거나 직접 고친다.

**6. 목록 반영**

```bash
python3 build_posts.py
```

를 실행해 `src/data/posts.js`를 다시 굽는다. 그래야 홈페이지 블로그 탭에 나타난다.

## 보고

3줄 이내로 끝낸다:

- 저장 경로
- 총 글자수 / 제목 후보 3개
- `검토 필요` 항목이 있으면 그 개수와 종류 (`[의료광고]`, `[절세보장]` 등)

초안 파일은 `drafts/`에 그대로 둔다. 지우지 않는다.
