초안 파일 하나를 네이버 발행용으로 변환한다. 자동 발행은 하지 않는다.

## 대상

`$ARGUMENTS`

인자가 비어 있으면 **폴더를 스캔하지 말고** 그대로 멈춘다.
"변환할 초안 경로를 지정해 주세요. 예: `/naver-ready content/posts/drafts/가족인건비.md`" 라고만 답한다.

## 순서

**1. 초안 읽기 — 지정된 파일 하나만**

`$ARGUMENTS` 경로의 파일만 Read한다.
`content/posts/drafts/` 전체를 훑거나 Glob으로 다른 초안을 찾지 않는다. 지정된 하나만 처리한다.

파일이 없으면 경로를 그대로 알려주고 멈춘다.

**2. 프론트매터 확인**

`title`, `category`, `keywords`, `kb_refs`가 있는지 본다. (`tags`는 없으면 변환하며 채운다.)
`category`는 `content/categories.json` 의 `items[].id` 중 하나여야 한다.
값을 지어내지 말고 그 파일을 Read해서 고른다. 없는 분류가 필요하면
**임의로 만들지 말고** 무엇이 필요한지 알리고 멈춘다 — 카테고리는 네이버 블로그
메뉴와 맞춰야 하므로 사람이 정한다.
필수 항목이 비어 있으면 무엇이 없는지 알려주고 멈춘다. 임의로 채우지 않는다.

**3. KB 사실관계 보강 — kb_refs에 적힌 파일만**

프론트매터 `kb_refs`에 나열된 경로만 Read한다.
`kb_refs`가 비어 있으면 이 단계를 건너뛴다. **KB 폴더를 검색하지 않는다.**
읽은 내용은 초안의 사실관계(요건, 금액 기준, 근거 조문)를 확인·보강하는 데만 쓴다.

KB와 초안이 어긋나면 KB를 신뢰하되, 어긋난 지점을 기록해 두었다가 마지막 보고에 포함한다.

**4. 두 에이전트를 동시에 호출한다**

Agent 도구 호출 **두 개를 한 메시지에 같이 넣어** 병렬로 돌린다. 순서대로 돌리지 않는다.
글쓰기와 준법 점검은 서로를 기다릴 이유가 없고, 점검을 뒤로 미루면 빼먹게 된다.

| 에이전트 | 맡는 일 |
|---|---|
| `blog-agent` | 네이버 발행용 변환 → `ready/` 에 저장 |
| `ad-agent` | 같은 초안의 준법 점검 (파일은 건드리지 않는다) |

`blog-agent` 에 넘길 것:
- 초안 전문 (프론트매터 포함)
- 3단계에서 읽은 KB 내용 중 **관련 대목만** 발췌 (전문을 통째로 넘기지 않는다)
- 저장 경로: `content/posts/ready/<초안과 같은 파일명>`
- 프론트매터의 `status`는 `ready`로 바꾸고, `published_url`·`published_at`은 빈 문자열로 둘 것
- `content/posts/README.md`의 "ready/ 파일 형식" 구분자를 그대로 지킬 것

`ad-agent` 에 넘길 것:
- 초안 본문 (프론트매터는 빼도 된다)
- 네이버 블로그에 실릴 글이라는 것
- **준법 점검만** 하고 파일은 저장하지 말 것 (쓰기 권한이 없다)
- 걸리는 문구를 그대로 인용하고 어느 규정인지 밝힐 것

**5. 결과 병합 · 확인**

`blog-agent` 가 저장한 파일을 Read해서 아래를 확인한다:

- `=== 제목 후보 ===`, `=== 본문 ===`, `=== 이미지 제작 목록 ===`, `=== 태그 ===`,
  `=== 리포트 ===` 다섯 섹션이 다 있는가
- 본문의 `[이미지 n 삽입 위치]` 개수와 이미지 제작 목록의 항목 수가 같은가
- 본문에 마크다운 잔재(`#`, `**`, 줄 앞 `- `)가 남아 있지 않은가
- 말미 안내 문구가 있는가

그 다음 `ad-agent` 결과를 합친다:

- 지적된 것이 있으면 `=== 검토 필요 ===` 에 **`[준법]`** 항목으로 넣는다
- `ad-agent` 가 "확인 필요"로 표시한 것도 그대로 넣는다. 임의로 판단해 빼지 않는다
- 이미 같은 취지의 항목이 있으면 중복해서 넣지 않는다

**`blog-agent` 가 새로 만든 문장도 점검 대상이다.** 제목 후보 3개와 상담 유도 문구는
초안에 없던 텍스트다. 여기에 "1위", "전문", "무료 상담", "절세 보장" 같은 표현이
들어갔는지 직접 본다. 걸리면 `[준법]` 로 올리고 대체 문구를 함께 적는다.

어긋나면 에이전트에게 고치게 하거나 직접 고친다.

**6. 목록 반영**

```bash
python3 build_posts.py
```

를 실행해 `src/data/posts.js`를 다시 굽는다. 그래야 홈페이지 블로그 탭에 나타난다.

## 보고

4줄 이내로 끝낸다:

- 저장 경로
- 총 글자수 / 제목 후보 3개
- `검토 필요` 항목이 있으면 그 개수와 종류 (`[근거]`, `[수치]`, `[준법]` 등)
- **준법 점검 결과** — 걸린 문구가 있으면 몇 건인지, 없으면 "준법 이상 없음"

초안 파일은 `drafts/`에 그대로 둔다. 지우지 않는다.
