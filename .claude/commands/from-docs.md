세무 서류에서 블로그 초안을 만든다. 발행은 하지 않는다.

예전 `pipeline/` 이 하던 일을 에이전트로 옮긴 것이다. API 키가 필요 없다 —
Claude 가 PDF·이미지를 직접 읽는다.

## 대상

`$ARGUMENTS`

인자가 비어 있으면 **폴더를 찾아 헤매지 말고** 그대로 멈춘다.
"서류 폴더를 지정해 주세요. 예: `/from-docs work/docs/2026-09`" 라고만 답한다.

## 순서

**1. 경로 확인**

지정된 경로가 `work/` 아래인지 본다. **아니면 멈춘다.**
세무 서류는 과세정보이자 개인정보다. `work/` 밖에 두면 안 되고, 거기서만 읽는다.

Glob 으로 그 폴더의 PDF·이미지만 센다. 파일이 없으면 경로를 알려주고 멈춘다.

**2. `doc-reader-agent` 에 판독을 맡긴다**

넘길 것:
- 서류 파일 경로 목록
- 판독 결과를 쓸 경로: 같은 폴더의 `판독.md`
- **수치를 옮기는 것까지만** 하고 세무 판단은 하지 말 것

돌아온 결과에서 `판독불가` 와 `눈에 걸리는 것` 을 따로 챙겨 둔다. 마지막 보고에 넣는다.

**3. 쟁점을 고른다 — 여기는 내가 판단한다**

판독 결과를 읽고, 블로그 글감이 될 쟁점을 **하나** 고른다. 여러 개를 한 글에 담지 않는다.

고르는 기준:
- 그 서류에서 실제로 문제가 될 수 있는 지점인가
- 같은 상황에 놓인 사람이 많은가 (한 거래처에만 해당하면 글감이 아니다)
- 검색할 만한 말로 표현되는가

고른 쟁점과 이유를 한 줄로 적어 둔다.

**4. `blog-agent` 에 초안 작성을 맡긴다 (작성 모드)**

넘길 것:
- 3단계에서 고른 쟁점
- 판독 결과 중 **쟁점과 관련된 구조만** — 숫자와 상호는 넘기지 않는다
- 저장 경로: `content/posts/drafts/<쟁점을-담은-파일명>.md`
- 프론트매터의 `category` 는 `medical` 또는 `transfer` 중에서 고를 것

**넘기기 전에 내가 지운다.** 상호, 사업자등록번호, 실제 금액, 주소, 좁은 업종.
`blog-agent` 가 걸러 줄 것이라고 믿지 않는다 — 안 넘기면 샐 수가 없다.

금액 예시가 꼭 필요하면 **둥근 가상의 숫자로 바꿔서** 넘기고,
그 사실을 초안 말미 `검토 필요` 에 적게 한다.

**5. 확인**

`blog-agent` 가 저장한 초안을 Read 해서 본다:

- 프론트매터에 `title`, `category`, `keywords` 가 있는가
- 특정 거래처를 짚어 낼 수 있는 서술이 없는가

그리고 **눈으로만 보지 말고 기계로 한 번 더 훑는다.** 눈은 놓친다.

판독 결과에서 상호·성명·사업자등록번호·업종코드·주소·금액을 뽑아
초안에서 grep 한다. 하나라도 나오면 멈추고 고친다.

```bash
F=<초안경로>
for w in <상호> <사업자등록번호> <금액1> <금액2> …; do
  grep -q "$w" "$F" && echo "  ✗ 발견: $w"
done
```

**본문에 나온 숫자를 전부 뽑아 하나씩 확인한다.** 남아 있어도 되는 것은
`blog-agent` 에게 쓰라고 한 가상의 숫자뿐이다.

```bash
grep -oE '[0-9][0-9,]*(만|억)?\s*원?' "$F" | sort -u
```

검색어가 너무 짧으면(예: `의원`) 무관한 곳에 걸린다. 걸린 자리를 앞뒤와 함께
확인해서 진짜 유출인지 본다.

하나라도 걸리면 고치거나 `blog-agent` 에게 고치게 한다.

## 보고

4줄 이내:

- 판독한 서류 수 / `판독불가` 건수
- 고른 쟁점과 이유
- 저장된 초안 경로
- 다음 할 일: `/naver-ready <초안경로>`

**변환까지 하지 않는다.** 초안을 사람이 한 번 읽은 뒤에 `/naver-ready` 로 넘긴다.
그 사이가 거래처 정보가 새는지 보는 마지막 지점이다.
