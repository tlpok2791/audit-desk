# work/ — 감사 작업 데이터

**이 폴더의 내용은 절대 커밋되지 않는다.** `.gitignore`에 `work/*` 로 막아 두었고
이 README 하나만 예외로 두었다.

과세정보·개인정보가 들어가는 자리이므로 규칙을 바꾸지 않는다.

## 구조

작업 단위는 engagement — **회사 × 결산일** 하나가 폴더 하나다.

```
work/
  MAPLE/                      회사코드
    2025-12-31/               결산일
      meta.json               회사명·코드·결산일·작성자·검토자·중요성금액·수행중요성
      worksheet.json          정산표 (탭1 산출물, 탭2~5의 단일 소스)
      FY25_MAPLE_worksheet.xlsx   정산표 엑셀
```

회사코드는 폴더 이름이 되므로 영문·숫자·하이픈만 쓴다 (화면에서 검사한다).

## 파일이 여기 들어오는 방법

브라우저는 보안상 디스크에 직접 쓸 수 없다. 그래서 홈페이지는 파일을 **내려주기만** 하고,
사람이 위 경로에 넣는다.

1. 감사도구 탭 → 탭1 정산표 작성
2. engagement 등록 → 전기 재무제표·당기 시산표 업로드 → 수정·재분류분개 입력
3. "정산표 저장" → `worksheet.json` 이 내려받아진다 → 위 폴더에 넣는다
4. "정산표 xlsx 내려받기" → 엑셀 산출물

작업 중에는 브라우저 IndexedDB에도 자동 보관되므로 새로고침해도 남아 있다.
다만 브라우저 데이터를 지우면 사라지니, 끝낸 작업은 반드시 파일로 내려받아 둔다.

## 다시 불러오기

새로고침했거나 다른 PC에서 이어서 할 때는 각 탭 상단의 **"정산표 불러오기"** 로
`worksheet.json` 을 고르면 된다. 파일의 meta 를 보고 engagement 도 함께 맞춰진다.

## 업로드한 엑셀은 어디로도 가지 않는다

엑셀 파싱은 SheetJS로 브라우저 안에서만 한다 (`vendor/xlsx.full.min.js`).
서버가 없으므로 업로드한 원장·시산표가 외부로 전송되지 않는다.
